## 決めたこと・理由

| 決めたこと | 理由 |
|---|---|
| 旧 SD を全体イメージで保存してから、まっさらから作り直す | 旧 SD の中身の経緯（誰がどう入れたか）が分からず、ssh に入れなかった。本人の指示 |
| Ubuntu 22.04.5 + ROS 2 Humble、公式イメージではなく Ubuntu Server から | ROBOTIS の SBC Setup（Humble）は、事前ビルドのイメージが Noetic 用だけで、Humble は Ubuntu 22.04.5 Server に自分で導入する手順（ROBOTIS のページを要約したもの。**本文は確かめていない**） |
| ssh は鍵のログインだけ。パスワードは無効（新しい SD の `user-data` で `ssh_pwauth: false`、`lock_passwd: true`、`sudo` はパスワードなし） | 作業中の判断（本人の明示の指示ではない）。パスワードを持ち回らないため |
| OpenCR を `turtlebot3_manipulation` のファームウェアにする | 合っていないと全関節が -π のまま（[02](02-robot-provisioning.md)） |
| 旧 home をやめて、OMX 標準の折りたたみ姿勢を HOME にする | 今の 0 位置では joint3 が限界を超え、自己衝突 23.5 mm（MuJoCo） |
| 純正の制御プラグインにパッチを当てて、通信を減らす | 1 周期 7 回の通信で 5 Hz → カクカク。OpenCR は 1 秒に 43 回しか答えられない。公式をそのまま使い、差分だけを持つ（`814f140` に当たる） |
| 腕の軌道を、先 1.5 秒ぶんまとめて渡す | 20 Hz の 1 点ずつより、コントローラが組み直さず、なめらか |
| 心拍と、機体側の見張り（0.3 秒）を足す | 軌道を先まで渡すと、PC が落ちても動き続けるため。「PC との接続が切れたら断絶する」という本人の要求 |
| 機体の ROS 2 を Wi-Fi の IP だけにする | 有線を切ったとき、`ros2_control_node` のトピックが PC に届かなくなった（再起動で直った）。有線を抜き差ししても壊れない構成にしたい。Wi-Fi は固定 IP、のちに「起動のたびに IP から作る」に変更（DHCP でも動く） |
| PC 側は、機体の IP へ直接も発見を呼びかける | Wi-Fi 越しのマルチキャストの発見が遅い（新しいプロセスで約 10 秒） |
| 画面から動かす前に、MuJoCo で衝突を判定する | 本人の要求「腕の形をたくさんシミュレートして、動ける範囲を徹底して求めて」。その結果を画面の安全に使った |
| Orbit は LiDAR で進路を見て止まる | 人や物に当たらないように |
| 姿勢・動作列の保存先をリポジトリの外（`TB3_DATA_DIR`）にする | 個人のデータで git を汚さない |
| `tb3ctl` で、機体への導入・設定・PC 側の起動をまとめる | 「簡単なセットアップで、他の人が、他の PC・他のネットワークで動かせる」という本人の要求 |

## 画面の見た目

TRUST ME（本人の別プロジェクト。赤と琥珀色、警告テープ、計器、「Peace Industries」）の見た目を参考にして、と言われて作った。そのあと「もっとメタリックな感じに」と言われてクロームの縁・ヘアラインの鋼板・削り出しのボタンにした。「デストロイヤーとかいうのなし」と言われて、機体の呼び名を `TB-3 COMPANION` に変えた（mDNS のホスト名 `turtle-destroyer` は機体のホスト名としてそのまま残っている）。画面の中の `Peace Industries` の文字は TRUST ME 由来（[NOTICE.md](../NOTICE.md)）。
